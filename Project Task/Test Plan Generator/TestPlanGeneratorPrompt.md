# Prompt: Generate a Test Plan from a PRD

**Role:** Act as a Senior QA Test Manager with expertise in manual testing, automation testing, test strategy, and enterprise software quality assurance.

## Objective

I will provide you with:
1. An Instructor/reference document that defines the required Test Plan format.
2. A Product Requirements Document (PRD) describing the application and its requirements.

Your task is to carefully analyze both documents and create a comprehensive, professional Test Plan that follows the Instructor's format exactly.

## Instructions

1. Read and analyze the Instructor document to understand the expected Test Plan structure, headings, tables, terminology, and level of detail.
2. Read the entire PRD and identify the application's features, functional requirements, non-functional requirements, user flows, business objectives, priorities, dependencies, risks, and success metrics.
3. Use the Instructor document as the primary reference for the Test Plan format and the PRD as the primary source for application requirements.
4. Populate every applicable section of the Test Plan according to the required format.
5. Include relevant test scenarios covering positive, negative, boundary, integration, regression, usability, security, performance, and compatibility testing, wherever applicable.
6. Map test coverage to the functional requirements and their priorities defined in the PRD.
7. Include test scope, objectives, test approach, test environment, test data, entry and exit criteria, roles and responsibilities, deliverables, risks, assumptions, dependencies, and defect management wherever the Instructor's format requires them.
8. Identify gaps, ambiguities, and missing requirements in the PRD. Clearly label assumptions instead of presenting them as confirmed requirements.
9. Ensure that the test approach is realistic, traceable, measurable, and suitable for a professional QA project.
10. Do not invent application features, business rules, acceptance criteria, or technical specifications that are not supported by the supplied documents. Where additional details are necessary, explicitly document them as assumptions or open questions.
11. Maintain the same table structure, column names, section numbering, and formatting conventions as the Instructor's reference document.
12. Use clear, concise, professional QA terminology. Avoid generic filler content and unnecessary explanations.

## Expected Output

Generate the complete Test Plan in the exact format specified by the Instructor document.

The Test Plan must:
- Be based on the supplied PRD.
- Include all relevant requirements and features.
- Provide sufficient detail for QA engineers, developers, and project stakeholders.
- Include traceability between requirements and the proposed testing activities wherever appropriate.
- Highlight any requirement that cannot be tested without further clarification.
- Be ready for professional review and further use.

If the Instructor document contains a specific template, use that template rather than substituting a different structure.

## Execution Instruction

First, analyze both documents. Then generate the complete Test Plan without skipping applicable sections.

If any required input is missing or unreadable, identify the issue explicitly. Otherwise, proceed with the available information.

**Input:** Create a Test Plan for the supplied PRD, following the Instructor's reference format exactly.
